> 더마 선케어 브랜드 **셀퓨전씨(씨엠에스랩)** 를 위한, K-뷰티 경쟁 브랜드의 글로벌·국내 동향을
> **자동 수집 → AI 분류·번역 → 다축 신호 삼각검증 → 대시보드·Slack 브리핑·Q&A 봇**으로
> 연결하는 엔드투엔드 경쟁 인텔리전스 파이프라인.

**🔗 라이브 대시보드:** https://cmslab-rival-monitor.onrender.com

이 문서는 **무엇을 만들었는가**뿐 아니라 **왜 그렇게 설계했는가(의사결정 로그)** 를 함께 담았습니다.

## 핵심 아이디어 — 다축 삼각검증

이 프로젝트의 출발점이자 차별점. **뉴스만 보면 "발표(PR)"에 속는다**는 문제의식에서 시작했다.

경쟁사가 "브라질 진출!"이라고 보도자료를 뿌려도, 그게 **진짜 무브인지 PR 노이즈인지** 뉴스만으론 알 수 없다. 그래서 서로 다른 성격의 신호를 겹쳐 **교차검증**한다:

```
      발표/의도                    실제 성과                       선행
 ┌────────────────┐    ┌───────────────────────────────┐   ┌────────────┐
 │  📰 뉴스(공급)  │    │  📦 수출 (관세청)             │   │ 🪧 상표출원 │
 │  🔍 검색 (수요) │──▶ │  💰 재무 (NICE·비상장 포함)   │◀──│  (KIPRIS)  │
 │  네이버(국내)   │    │  🛒 리테일 실판매             │   │ 진출 임박? │
 │  구글(글로벌)   │    │   · 아마존 해외 9개국 랭킹     │   │(뉴스보다 앞)│
 │                 │    │   · 올리브영 국내 랭킹·리뷰    │   │            │
 └────────────────┘    └───────────────────────────────┘   └────────────┘
       수요·의도                   하드 아웃컴                   조기 신호
```

**대표 예시 (실제 수집 데이터):**
> "조선미녀 브라질 진출" 뉴스 → 🔍 브라질 관련 검색 확인 → 📦 **브라질 화장품 수출 +89% YoY**(관세청) 동반 → **실질 무브로 검증**.
> 반대로 뉴스는 뜨는데 검색 수요가 식으면 → **PR 노이즈 의심**으로 라벨링.
> 🛒 여기에 **실판매**까지: "Centellian24 마데카크림 미국 확장" → 아마존 크림 카테고리 #10 + 국내 올영 실랭킹으로 "진짜 팔리나" 최종 확인.

## 북극성 서사 — 무엇이→왜→우리가 할 것

이 시스템이 최종적으로 답하려는 질문:
**"어느 나라에서 어느 브랜드가 어떻게 사업을 펼치고(무엇), 어떤 제품이 왜 잘 나가며(왜), 그래서 우리(셀퓨전씨)가 할 것은 무엇인가."**

- **무엇이 잘나가나** — 아마존·올리브영 실랭킹 + 순위 추세(누가 뜨고 지나) + 뉴스 무브.
- **왜** — 올영 리뷰 감성(긍정/부정 키워드·평점) + 경쟁 신제품 성분 지형(PDRN·엑소좀 등).
- **그래서 우리가 할 것** — AI가 위 신호를 종합해 셀퓨전씨의 더마·선케어 강점으로 **독자 대응 액션 한 줄**을 생성. 경쟁사 리뷰 약점(예: 지속력·트러블·패키징 불만)을 우리 공략 포인트로 되받아침.

브리핑 탭 최상단 **"지금 대응해야 할 것"** 배너 = 최근 7일 신규 HIGH 움직임 기반. 각 항목엔 **"근거 보기"** 펼침 패널(모멘텀 배수·아마존/올영 순위·원본 기사)이 연계되어 "왜 이 대응이 필요한가"를 즉시 확인.

## 개발 스토리 & 의사결정 로그

시간순으로, **각 기능이 왜 추가됐고 어떤 판단을 했는지**.

### 1단계 · 뉴스 수집 + AI 분류 (기반)
- **문제:** 경쟁사 해외 동향이 여러 나라·언어·매체에 흩어져 있어 수작업 추적 불가.
- **결정:** 인증 불필요한 **공개 RSS/API 8종**으로 수집(구글뉴스·전문지 30피드·장업신문·PRTimes·네이버·Reddit·YouTube). 유료 크롤링/스크래핑 배제 → 유지보수 부담 최소화.
- **결정:** 수집 즉시 저장하지 않고 **2단계 AI 분류**(gpt-4o-mini). Stage1 관련성 필터 → Stage2 구조화(활동유형·중요도·전략스코어·근거수준·번역). *왜 2단계?* 노이즈 기사를 싸게 먼저 거르고 비싼 구조화는 통과분만 → 비용 절감.
- **결정:** `country`(기사가 다루는 시장) ≠ `source_country`(수집 실행 국가)로 분리. 크로스마켓 추적을 위해.

### 2단계 · 중복 병합 (신호 품질)
- **문제:** 같은 사건을 20개 매체가 조금씩 다른 제목으로 보도 → 대시보드·브리핑 오염.
- **결정:** `title+details` **의미 임베딩**(text-embedding-3-small) 코사인 유사도로 브랜드 내 같은 사건을 union-find 클러스터링, 대표 1건만 남김(`is_duplicate`, 되돌리기 가능). **같은 활동유형만** 병합해 오병합 방지. (실측 ~31% 병합)

### 3단계 · 티어 자동 조정 (운영 자동화)
- **결정:** **모멘텀 기반 자동 승급/강등**. 최근 4주 vs 직전 4주 기사량 비율로 Rising/Stable/Cooling 판정. **쿨다운 14일**로 플립플롭 방지.

### 4단계 · 대시보드 · 브리핑 · Slack Q&A 봇 (전달)
- **결정:** 대시보드는 서버사이드 HTML 생성(Chart.js/Canvas 인라인) → 단일 FastAPI로 배포.
- **결정:** 브리핑 2종 — 일간(gpt-4o-mini) / 주간(gpt-4o). 용도별 모델 분리로 비용/품질 균형.
- **결정:** Slack Q&A 봇을 **MCP 서버**로 구현. 분석 쿼리를 조회 전용 툴로 노출 → 봇(gpt-4o)이 자연어 질문에 맞는 툴 호출. Render web 프로세스 내 **in-process**.

### 5단계 · HIGH 속보 정제 (알림 피로 해결)
- **결정:** `strategic_score ≥ 85` + 스쳐언급 제외 게이트 → ~5건/일로.
- **결정:** **발송 시점 중복 게이트**(`high_alert_log`). 최근 72h 내 같은 사건이면 억제. 같은 사건 판정 = 문자유사도 ≥0.50 **또는 3-gram Jaccard ≥0.20**(한국어 강건). → 7중 발송이 1건으로.

### 6단계 · 외부 신호 계층 (도약) ⭐
- **문제의식:** 지금까지 데이터는 전부 **공급/PR 신호**. 빠진 건 **수요·성과·선행**.
- **아키텍처:** 기사가 아니므로 **별도 `signals/` 패키지** + 전용 테이블 + 주기 fetch + 상관분석으로 분리.
- **6a. 네이버 검색 트렌드(국내 수요)** — real/pr/latent 판정. *교훈:* API HUB 이관으로 공식 문서가 전부 틀린 엔드포인트를 안내 → 직접 탐침으로 발견.
- **6b. 관세청 수출통계(시장 성과)** — HS 3304 국가별 수출액. "왜 이 시장이 크는가" 성장 스토리로 발전.
- **6c. DART 재무(회사 성과)** — 매출·영업이익·성장률. *한계:* 상장사만(비상장 외감 불가) → 9단계에서 NICE로 대체·통일.
- **6d. KIPRIS 해외상표(진출 선행신호)** — 미국·일본 상표 = 뉴스보다 먼저. 비상장 공백을 메움(아누아 미국 신제품 상표 19건 사전 포착).
- **6e. 구글 트렌드(글로벌 수요)** — 글로벌·미국·일본 검색 + 급등 감지. *교훈:* pytrends 429는 브라우저 UA로 우회.

### 7단계 · 브랜드 소스 통일 (일관성 리팩터)
- **결정:** 공용 헬퍼 `get_active_brand_names()`(DB 기반)로 통일. **브랜드 1회 추가 = 뉴스+검색+구글+수출까지 자동 반영.**

### 8단계 · 리테일 실판매 (아마존 — "진짜 팔리나") 🛒
- **문제의식:** 수출(국가단위 거시)·재무(회사단위)는 있어도 **개별 제품이 실제 시장에서 몇 위로 팔리는지**가 없었다.
- **결정:** 아마존 **공식 베스트셀러(BSR)** 파싱 — 무자격증 공개 페이지, requests+bs4(브라우저 UA 필수, 기본 UA→503). US 세부 13노드(선케어·BB/CC 등 셀퓨전씨 핵심영역 특화) + JP·DE·GB·FR·IT·ES·AU·AE 광역 = **9개국**. `is_core` 플래그로 우리 주력 카테고리 강조.
- **발전:** 매일 스냅샷 축적 → **순위 추세 시계열 차트**(첫날 대비 delta, 스파크라인). "누가 뜨고 지나"를 실판매로.

### 9단계 · v2 재설계 (클라이언트 피드백 반영)
- **피드백(8/13):** ① 불투명한 점수(기회점수·종합스코어) 제거 → **객관 원본수치**(건수·%·배수·순위). ② **시장(국가) vs 경쟁사(브랜드) 분리**. ③ 기간필터 표준화 + 통합검색. ④ 브리핑 로직 일원화. ⑤ **NICE BizLine 재무로 통일**(DART 대체).
- **결정:** 대시보드를 목업 기반 **5탭**(브리핑·경쟁사·시장·재무·검색)으로 재편. 네이비/코발트 테마, WCAG AA 대비.
- **NICE BizLine 재무:** 산업경쟁현황 엑셀(46,719행: 기업×연도×[매출·영업이익·광고비]) 적재 → **비상장 포함** 화장품사 재무 통일. DART가 못 잡던 비상장 경쟁사까지 커버.
- **기간필터 A+B:** 프리셋(30/60/90) 즉시 스왑 + **임의 기간**(예: 26년 1분기)을 서버(`/api/period`)에서 조회.

### 10단계 · 북극성 서사 + 성분·악재 (맥락 완성)
- **결정:** **기회 스토리 카드** — 판독→제품(순위)→왜→시장포지션→**우리가 할 것**(AI 액션). 경쟁사 framing 방지 가드(경쟁사와 협업 액션 금지, 독자 대응만).
- **결정:** **성분 지형**(경쟁 신제품에 뜨는 성분 — PDRN·엑소좀 등 언급수·주도 브랜드) + **경쟁사 악재**(리콜·논란·규제 = 우리 반사 기회) 대시보드 노출. 분류기에 `key_ingredients`·`sentiment` 필드 추가.
- **시계열:** 브랜드 스코어 주간 스냅샷(`brand_score_history`) + 리테일 순위 추세.

### 11단계 · 올리브영 국내 채널 (국내 최대 H&B) 🇰🇷
- **문제의식:** 리테일이 아마존(해외)뿐 → **국내 최대 채널이 공백**. 사용자가 별도 구축한 올영 스크래퍼(리뷰·랭킹)를 **원격 채널 MCP**(`oliveyoung-review.vercel.app`, 무인증 Streamable HTTP 25툴)로 서빙 중임을 확인(데이터는 공유 Supabase가 아닌 원격 저장).
- **B 대시보드:** `signals/oliveyoung_channel.py`가 매일 `get_market_rankings`(8카테고리×Top20) 호출→브랜드매칭→`oliveyoung_rankings` 적재. 시장 탭에 **선케어(간판) 국내 랭킹 + 급변동 + 리뷰 감성** 3단 노출. 리뷰 감성 = 경쟁사 제품 평점·긍정/부정 키워드(`get_competitor_analysis`) → "왜 잘나가나/약점=공략".
- **A 챗봇:** `mcp_server.py`에 원격 MCP **라이브 프록시 5툴** 추가(랭킹·무버스·리뷰경보·리뷰비교·일일브리핑). 대시보드=적재(히스토리·견고), 챗봇=라이브(최신·풍부)로 역할 분리.
- **서사 연결:** 올영 리뷰 약점을 **기회카드 액션 생성 프롬프트에 주입** → "우리가 할 것"이 국내 리뷰 근거로 나오게.

### 12단계 · 근거 연계 UX + 배너 신선도
- **문제:** "지금 대응" 배너가 2주째 같아 보임. *원인:* 프롬프트가 4주 모멘텀 배수를 강제 인용 → 느린 최상위 브랜드가 고정. **수정:** 최근 7일 신규 HIGH 사건(날짜) 기반으로 전환 → 매주 갱신.
- **결정:** 배너 각 항목에 **"근거 보기"** 펼침 패널 — 그 브랜드의 신호 칩(모멘텀·아마존/올영 순위·검색 급등) + 근거 기사(HIGH top3·원문 링크) + 전체 드릴다운 연계. "왜 대응?"을 한 번 펼침으로 확인.
- **웹 챗봇:** Slack 봇의 `answer()` 로직을 재사용해 대시보드 검색 탭에 챗봇(`/api/ask`) 탑재.

## 하드-원 레슨(트러블슈팅 하이라이트)

| 문제 | 원인 | 해결 |
|---|---|---|
| 네이버 데이터랩 401 | API HUB 이관 + 공식 문서 엔드포인트 오답 | 게이트웨이 직접 탐침으로 실엔드포인트 발견 |
| 구글 트렌드 429 | pytrends 기본 UA 차단 | 브라우저 User-Agent 우회 |
| 아마존 503 | 기본 UA 봇 차단 | 브라우저 UA + 공식 BSR 노드(`/gp/bestsellers/beauty/{node}`) |
| NICE 46k행 적재 타임아웃 | 원격 DB 행단위 INSERT | executemany 배치(1000/batch) + Python dedup |
| 지도 마커↔드릴다운 불일치 | LIMIT 400이 소규모 시장 절단 | limit 2500 + 국가 신호 필터 정렬 정합 |
| 올영 테이블 못 찾음 | 데이터가 공유 Supabase에 없음 | 원격 Vercel MCP 뒤편 저장 확인 → MCP 프록시로 접근 |
| "지금 대응" 배너 고착 | 4주 모멘텀 배수 강제 인용 | 최근 7일 신규 사건(날짜) 기반으로 전환 |
| HIGH 속보 7중 발송 | 의미병합(23시)이 속보보다 늦음 | 발송 시점 중복 게이트(3-gram Jaccard) |
