# K-Beauty Competitor Intelligence

> 더마 선케어 브랜드 **셀퓨전씨(씨엠에스랩)** 를 위한 경쟁 인텔리전스 파이프라인.
> 34개 경쟁 브랜드의 글로벌·국내 동향을 **자동 수집 → AI 분류·번역 → 다축 교차검증 →
> 대시보드·Slack 브리핑·Q&A 봇**으로 연결한다.

**🔗 라이브:** https://cmslab-rival-monitor.onrender.com

이 문서는 **무엇을 만들었나**보다 **왜 그렇게 판단했나**에 무게를 둔다.
설계 판단, 틀렸던 가정, 그걸 어떻게 알아챘는지를 남겼다.

## 핵심 아이디어 — 다축 교차검증

출발점은 **"뉴스만 보면 발표(PR)에 속는다"** 였다.

경쟁사가 "브라질 진출!"이라고 보도자료를 뿌려도 그게 진짜 무브인지 PR 노이즈인지
뉴스만으론 알 수 없다. 성격이 다른 신호를 겹쳐 교차검증한다.

```
      발표·의도                     실제 성과                      선행
 ┌────────────────┐    ┌───────────────────────────────┐   ┌────────────┐
 │  📰 뉴스(공급)  │    │  📦 수출 (관세청)              │   │ 🪧 상표출원 │
 │  🔍 검색 (수요) │──▶ │  💰 재무 (NICE·DART·컨센서스)  │◀──│  (KIPRIS)  │
 │  네이버 · 구글  │    │  🛒 리테일 실판매              │   │ 진출 임박? │
 │  📺 유튜브 버즈 │    │   · 아마존 9개국 · 올리브영     │   │(뉴스보다 앞)│
 └────────────────┘    └───────────────────────────────┘   └────────────┘
       수요·의도                   하드 아웃컴                   조기 신호
```

**실제 사례:** "조선미녀 브라질 진출" 뉴스 → 브라질 화장품 수출 +89% YoY(관세청)
동반 → 실질 무브로 검증. 반대로 뉴스는 뜨는데 검색·판매가 안 따라오면 PR 노이즈로 본다.

## 설계 판단 기록

### 왜 2단계 분류인가
수집 즉시 저장하지 않고 **Stage1 관련성 필터(gpt-4o-mini) → Stage2 구조화(gpt-4o)**.
노이즈를 싸게 먼저 거르고 비싼 구조화는 통과분만 태운다. 배치 16건/콜 —
32까지 올렸더니 응답 JSON이 `max_tokens`에서 잘려 배치가 통째로 날아갔다.

### 제목만으로 분류하고 있었다
구글뉴스 RSS는 본문을 안 준다. `link`는 리디렉션이고 `summary`는 제목을 감싼 링크
HTML이다. 그래서 **6,564건이 제목 한 줄로만 분류돼 있었다.**

두 번 실패한 뒤, `news.google.com/_/DotsSplashUi/data/batchexecute`에
`Fbv4je` 요청을 보내면 실제 발행사 URL이 나온다는 걸 찾아 본문 수집을 붙였다.
과거분을 백필해 **본문 확보율 35% → 89%**, 구글RSS는 2% → 88%.

본문이 생겼으니 다시 분류했다 — 5,490건 중 **4,957건의 전략점수가 바뀌었다.**
제목만으로는 거의 다 틀리게 매기고 있었다는 뜻이다. 비용 $1.47.

### 적중표 — 도구가 스스로 채점한다
브리핑은 매일 "이걸 지켜보라"고 말해왔는데, 한 달 뒤 실제로 어떻게 됐는지
아무도 대조하지 않았다. 주장만 쌓이고 결과와 이어지지 않았다.

과거 브리핑 100건에서 '지켜볼 것'을 뽑아 우리 데이터로 채점한다 —
관세청 수출·올리브영 순위·해외 리테일 순위·기사량. 실제로 붙는다:
*센텔리안24 올영 루온셀 입점 → 최고 11위에서 2위로*.

**못 맞히는 건 맞힌 척하지 않는다.** 틱톡샵 매출·SNS 증가 속도는 수집을 안 하므로
"수집하지 않는 지표"라고 그대로 적는다. 여기서 얼버무리면 적중표 자체를 못 믿게 된다.

### 대시보드 3.8MB → 2.0MB
30·60·90일 기사를 전부 HTML에 박고 있었다. 합쳐서 1.8MB인데 대부분은 기간을
바꾸지 않는다. 게다가 `HIGH_DATA`가 `PERIOD_DATA[기본기간].articles`와
**완전히 같은 배열**이었다(833건·364KB를 두 번). 기본 기간만 싣고 나머지는
누를 때 받는다.

### 브랜드를 늦게 추가하면 여기저기서 조용히 빠진다
슬랙 봇으로 승인한 브랜드는 DB에만 들어가는데 코드는 `config/brands.py`를 본다.
그래서 같은 브랜드가 기능마다 따로 빠진다 — 아마존 플래그, 상표 자사판정,
NICE 재무 매칭, 한글명 검색. **메디큐브가 아마존 8개국 1위인데 '미등록'으로
찍혀 있었고**(1,914행), 재무 탭에서는 통째로 빠져 있었다.

지금은 DB 브랜드명을 config로 들여오고, `canonical_brand()`로 표기 차이
(`TirTir` vs `Tirtir`)를 흡수하며, NICE 매칭은 브랜드 추가 후 재계산한다.

## 틀렸던 가정들

설계할 때 맞다고 생각했다가 데이터가 아니라고 알려준 것들.

| 가정 | 실제 | 어떻게 알았나 |
|---|---|---|
| YouTube `regionCode`로 국가별 버즈를 가를 수 있다 | **US·JP·GB 결과가 글자까지 동일.** 이 파라미터는 '그 나라에서 시청 가능한가'를 거를 뿐 | 붙이기 전에 3개국 실제 호출로 비교 |
| 국가가 안 되면 국가별 조회수라도 | YouTube API는 국가별 조회수를 **아예 안 준다**(자기 채널 Analytics 전용) | API 문서·응답 확인 |
| → 대안 | 영상 **언어**(`defaultAudioLanguage`)가 시장의 가장 가까운 대리지표. **추가 비용 0** — 이미 받아오면서 버리던 필드였다 | 아누아는 러시아어권이 영어권의 2배 |
| 상표 출원인 이름에 브랜드가 들어가면 자사 출원 | `ABIB`가 `HABIB AMERICAN BANK`(하비브은행) 안에 들어간다. 자기출원 29건 중 25건이 은행·러그회사·우주건축 | 토큰 경계 매칭으로 교체, DB 32행 정정 |
| 랭킹에 처음 보이면 신규 진입 | 브랜드를 늦게 등록하면 데이터도 늦게 쌓인다. 그걸 '진입'으로 읽으면 거짓말 | 카테고리·브랜드를 각각 2주 이상 본 뒤 나타난 것만 인정 |
| DART 분기보고서 금액은 그 분기 실적 | `thstrm_amount`는 3개월 단독, 누적은 `thstrm_add_amount`. 섞으면 반기가 2배 과소 | 비율이 0.236(기대 0.5)인 걸 보고 발견 |

Render에 스케줄러를 두면 같은 잡이 두 곳에서 돌아 중복 수집·중복 알림이 난다.

## 계층별 상세

**수집기** (`collectors/`) — `google_rss`(본문 복원 포함) · `media_rss`(전문지 30피드) ·
`jangup` · `prtimes`(JP) · `naver_news` · `reddit` · `youtube` · `body_fetcher`

**분류** (`classifier/`) — 2단계, 배치 16건/콜. 필드 18종: `activity_type`(9종) ·
`importance` · `strategic_score` · `brand_focus`(primary/secondary/incidental/unrelated) ·
`evidence_level` · `key_ingredients` · `sentiment` · `title_ko` · `article_body_ko` 등

**신호계층** (`signals/`, 13종) — 네이버·구글 검색 트렌드 · 관세청 수출 ·
NICE 재무(비상장 포함) · DART 분기 · **네이버 증권 컨센서스**(추정 실적) ·
KIPRIS/EUIPO 상표 · 아마존 9개국 · 올리브영 · 유튜브 버즈(언어권별) ·
성분 인텔 · **신흥 브랜드 자동발견**

**분석** (`analytics/`) — 모멘텀·수요 삼각검증·성장 스토리·기회 액션 생성 ·
**적중표**(`watch_scoreboard`) · 브리핑 전략 프롬프트

**노출**
- **대시보드 7탭** — 브리핑(적중표·주간종합) / 경쟁사(리더보드·상표·성분·악재) /
  시장(지도·수출·카테고리) / 재무(NICE+DART+추정) / 기록 / 검색(AI 챗봇) / 데이터 탐색
- **Slack** — 일간·주간 브리핑 + HIGH 속보 + Q&A 봇(MCP)
- **AI 파수꾼** — 수집 헬스·분류 드리프트 자가진단 후 이상만 Slack 보고

## 기술 스택 · 설치

| | |
|---|---|
| 서버 | FastAPI + uvicorn (Render) |
| 스케줄러 | APScheduler (로컬 상시, Windows 작업) |
| DB | Supabase PostgreSQL · SQLAlchemy |
| AI | gpt-4o-mini(필터·일간) / gpt-4o(분류·주간·챗봇) / text-embedding-3-small(중복병합) |
| 봇 | slack-bolt(Socket Mode) + MCP(streamable-http) + 웹 챗봇 |
| 외부 | 네이버 API HUB · 구글트렌드 · 관세청 · NICE BizLine · KIPRIS · EUIPO · DART · 네이버 증권 · 아마존 BSR · 올영 MCP |

```bash
cd CellFusionC_intel
pip install -r requirements.txt
cp .env.example .env            # 키 입력
python cli.py init-db           # 최초 1회
uvicorn server:app --port 8000  # 대시보드
python cli.py run               # 스케줄러
```

CLI: `init-db` · `collect -b -c` · `query` · `drill` · `report` · `collect-all -t`
